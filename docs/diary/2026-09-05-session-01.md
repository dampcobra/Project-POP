# Development diary — 2026-09-05 — Session 01

**Branch:** `spike/3-registration-recesses` (PR #4, still open and unmerged)

## Decision taken

Andy and Elara: **decouple backing thickness from `H` now**, rather than waiting
for the product model. ADR 0002 decision 8 had flagged this as a consequence of
adopting `D = 0.80 mm`; Session 01 adopts it so nothing gets built on the coupled
assumption.

`0.80 mm` remains the provisional measured default for the artwork/interface
depth. The backing is a separate physical property and does not inherit it.

## What the coupling actually was

One constant and four references. `STACK_BACKING_MM = 0.8` carried the comment
*"Kept at H so the intended 0.8 / 1.6 / 2.4 mm result is genuinely validated"* —
the backing was 0.8 mm **because** `H` is 0.8 mm, which is a coincidence of the
spike rather than anything physical. Nothing about a structural member follows
from how tall one artwork level looks.

The coupling was also latent in the **test suite**, which pinned the literals
`[0.8, 1.6, 2.4]` in three places. Those literals are only correct for a backing
equal to `H`, so leaving them would have re-coupled the two through the tests
even after the constant was fixed. They now assert the *relationship* —
`tops = backing + n·H` — and the as-printed literals are pinned separately
against the as-printed backing.

## What replaced it

`MIN_RECESS_FLOOR_MM = 0.4` — the minimum material left beneath a recess, two
layers at 0.20 mm. **Named for the first time.** It had existed only as a number
checked inside individual tests, which is part of why the backing's thickness
looked like a free choice rather than a consequence.

`BACKING_THICKNESS_MM = 1.2` — an independent structural property with its own
rule:

    backing = deepest recess it hosts + minimum recess floor
            = 0.80 + 0.40 = 1.20 mm

`ROUND1_AS_PRINTED_BACKING_MM = 0.8` — history, not a default. Kept so the
article Andy printed stays reproducible from the code, with a test proving that
configuration still yields 0.8 / 1.6 / 2.4.

`build_stack()` now takes `backing` as a parameter rather than reaching for a
module constant.

## Implications found while doing it

**The demo stack changed height.** It finishes at 1.2 / 2.0 / 2.8 mm rather than
0.8 / 1.6 / 2.4, and the regenerated `stack_*.stl` no longer match the printed
round-1 article. That is correct — the model should reflect the current decision
— but it means the committed STLs and the photographed evidence are now
deliberately different configurations. Both are reachable; the docs say which is
which.

**The default sits exactly at the minimum floor.** 0.40 mm of material under the
recess, two layers. It is the rule's output, not a margin. Raising
`MIN_RECESS_FLOOR_MM` is how to buy margin. Flagged as an open question rather
than decided.

**`0.80 + 0.40` is 1.2000000000000002.** Computing the default would have leaked
that into exported geometry and reports, so the value is a literal and the
derivation is asserted by test instead.

**The follow-up fixture keeps its own 1.6 mm.** It was deliberately over-thick so
floor thickness could not confound the fit experiment, which is a different
requirement from the product backing's. Two separate concepts that happened to
be adjacent; they stay separate.

## Result

181 tests green. Both pipelines PASS. Six new tests pin the decoupling,
including one asserting a backing equal to `H` genuinely cannot host the measured
default — the failure that motivated the decision.

Not started: the wider product model.

## Open question preserved

Andy and Elara, on merge: **1.2 mm is acceptable as the current provisional
engineering default, but the 0.40 mm floor is not treated as physically
validated in the same way as the 0.80 mm engagement depth.**

That distinction is easy to lose precisely because the backing is *derived* from
a measured number — derivation makes it look measured. It is now recorded in
three places rather than one: ADR 0002 deferred list, ADR 0002 evidence table
(as its own row, explicitly not held to the depth result standard), and the
`params.py` docstrings, with a test pinning the wording so a refactor cannot
quietly drop it.

No print has ever exercised a 0.40 mm floor beneath a loaded registration recess
on the member everything else glues to.
