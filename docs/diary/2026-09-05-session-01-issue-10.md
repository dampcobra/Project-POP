## The fixtures

Two, chosen to combine behaviours rather than isolate them:

```

             +- B(red)                   level 1
                +- C1(blue)              level 2   } siblings
                |  +- D(white)           level 3   }
                +- C2(yellow)            level 2   }
```

The plaque carries four levels, two siblings, a hole hosting nothing, and four

Deliberately not one enormous fixture: a failure in either points at a small

## Registration freedom, generalised

Spike 02 measured this over exactly two seatings. The meaning is unchanged, only
generalised:

```
worst-case freedom of a descendant relative to an ancestor
    = sum of the per-side seating clearances along that ancestry path
```

`FabricationResult.registration_freedom(ancestor, descendant)`, with
`seating_path()` alongside it so the path itself is inspectable. Two properties
matter more than the arithmetic:

**It walks the derived bodies, not the artwork.** What accumulates play is an
actual seating, and only a body that hosts a pocket provides one. Under a
strategy that seats nothing — the future island insert — the chain is empty and
so is the freedom, with no special case needed.

**It is ancestry-path accumulation, not stacking-level accumulation.** `C1` and
`C2` sit at the same level and seat into the same parent, but not into each
other. Asking for the freedom between them raises rather than returning a
number, because there is no answer rather than an answer of zero.

No reporting subsystem. Two methods on the result that already existed.

## What the architectural test turned up

The ticket's standard: if these tests need awkward bypasses, special cases or
knowledge of internals, the interface is wrong. Three things to report, none of
them a bypass.

**One addition was needed, and it is the one the ticket anticipated.** Nothing
else. Every other assertion in 41 tests is public API — `body_for`, `level_of`,
`voids_of`, `hosts`, `hosted_regions`, `pocket_for`, `floor_beneath`, `z`,
`to_dict`. No test reaches into a private attribute or reconstructs internal
state.

**`Pocket` does not record the clearance it was cut at**, so
`registration_freedom` reads it from the profile. That is correct while every
pocket is cut at the profile's clearance, which it is — and
`test_the_reported_freedom_matches_the_clearance_actually_cut` ties the reported
number back to the actual pocket geometry rather than trusting the profile
alone. But if a strategy ever varies clearance per pocket, the value belongs on
`Pocket` and the method should read it from there. Flagged in the docstring and
here; not changed, because nothing needs it yet and #10 is not the place to
speculatively widen the body model.

**Canonical output keeps declaration order in three places.** Found by writing
the different-declaration-order determinism test, which failed:

- vertex numbering — points are interned as first seen;
- hole order within `region_rings`;
- `colours()`, documented as first-seen and so order-dependent by design.

None of them reaches the derived result: the complete `FabricationResult` is
byte-identical across both declaration orders. Coordinates, ring sets, adjacency,
containment, colour set and every count match too. So this is internal identity
rather than content, and #7's determinism guarantee holds where it was claimed.

It is worth recording rather than quietly asserting around, because a reader
diffing two dumps of equivalent artwork would reasonably expect them to match.
`test_declaration_order_does_not_change_the_canonical_artwork_either` now states
the limit explicitly and asserts `to_dump() != to_dump()` deliberately, so the
distinction cannot rot into an accident.

## Scope boundaries held

**#19 not pulled in.** No mesh, no manifold work, no export, no plate, no
slicer. `test_the_derived_bodies_still_satisfy_the_extrusion_preconditions`
applies #9's agreed boundary to the new artwork — four and five levels, siblings,
a genuine void — and that is where it stops.

**The annular void was not solved.** A fixture could easily have wandered into
it, so instead of redesigning around the case silently, there is a test that
demonstrates the existing refusal is still clear:

```
hole 0 of region 'P' is only partly covered by its children, leaving a void
with a hole in it. A body footprint holds a flat list of void rings and cannot
express an annular void, so this is refused rather than mis-shaped.
```

**No colour-count limit was introduced.** There was none, and
`test_no_colour_count_limit_exists_in_the_pipeline` derives eight regions in
eight colours to keep it that way. Colour-count agnosticism is shown rather than
asserted about: recolouring every region — to one colour, to five distinct
colours — produces a byte-identical result, which could only fail if the
derivation consulted colour anywhere.

## Profile failures

Tested semantically — that the message identifies the bad quantity and says why
it is invalid — rather than against punctuation:

| case | asserted to name |
| --- | --- |
| backing too thin | `backing`, its value, what it must host, what it needs, `floor` |
| not a layer multiple | `seating depth`, `0.75`, the layer height, `layer`, `3.75` |
| body too thin to host its recess | the region `'B'`, what it leaves, the minimum it fails |

The third is the interesting one: the profile validates fine, and only stacking
artwork reveals the problem.
